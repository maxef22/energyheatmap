# История изменений

Формат: версия — что изменилось. Версия соответствует `<version>` в `web/info.xml`.

## 1.0.15 — 2026-11-02

### Исправлено
- Часы, помеченные как «связи нет», получали значение `1.0`, а при полярности «0 = нет связи»
  единица означает «связь есть». Из-за этого граничный блок считался нормальным и отчёт
  показывал 0 % расчётных при реальном обрыве. Теперь маркер ошибки ставится с учётом полярности.

## 1.0.14 — 2026-11-02

### Добавлено
- Признак обрыва по «замершему» счётчику: сплошной блок часов на границе месяца, где накопительное
  значение не растёт. Порог — настройка `frozenRunHours` (по умолчанию 12 ч), чтобы короткие ночные
  нули не попадали в расчётные.
- Тренд статуса используется только если он реально различает состояния (встречаются объекты,
  где он всегда равен `1`).

## 1.0.13 — 2026-11-02

### Добавлено
- Диагностика в ответе отчёта: распределение значений статуса по суткам, число часов с нулевым
  приростом в первых и последних сутках месяца, параметры тренда статуса.

## 1.0.12 — 2026-11-02

### Исправлено
- Полярность статуса по умолчанию приведена к фактической: `0` — связи нет, `1` — связь есть.
  Ранее трактовка была обратной, из-за чего «нет связи» оказывался весь месяц.

### Добавлено
- Настройка `statusErrorOnZero` — переключатель полярности без пересборки аддона.

## 1.0.11 — 2026-11-02

### Исправлено
- Месяц целиком может не читаться (SDK падает на отдельных записях цифрового тренда), из-за чего
  статус не определялся вообще. Теперь статус читается по суткам от краёв месяца; сутки, которые
  не читаются, считаются сутками без связи.
- Границы месяца учитывают и показания, и статус связи.

## 1.0.10 — 2026-11-02

### Добавлено
- Второй источник статуса — служебные метки в самом тренде потребления
  (`COMMUNICATIONS_DOWN`, `GATEWAY_DOWN`, `DEAD`, `FAILURE`, `UNKNOWN_VALUE`);
  раньше при недоступном тренде статуса заполнение не работало.
- Диагностика в JSON отчёта: `metersFailed`, `errors[]`, `diag[]`.

## 1.0.9 — 2026-11-02

### Исправлено
- Тренд статуса искался через строковый идентификатор, который не резолвился: отчёт показывал
  0 % по всем группам. Теперь точка статуса ищется как потомок узла-счётчика
  (`getParent`/`getChild`), без строковых id.
- Ошибка расчёта по одному счётчику больше не обнуляет всю группу.

## 1.0.8 — 2026-11-02

### Изменено
- Отчёт выполняется под соединением оператора с откатом на корневое.
- Ошибки по счётчикам попадают в ответ (`metersFailed`, `errors[]`) вместо молчаливого пропуска.

## 1.0.7 — 2026-10-13

### Изменено
- Новая методика расчёта расчётных значений: наработка = показание на конец месяца минус показание
  на начало; расчётным считается объём граничных блоков без связи; пропуски в середине месяца
  не учитываются; объём от сбросов счётчика восстанавливается статистикой, но в числитель не входит.
- Все расчёты в зоне `Europe/Moscow` (ранее был жёсткий сдвиг `+3 ч`).
- Источник статуса — настраиваемый тренд (`com_st_min` по умолчанию) вместо `cons_total_field_tn`.
- В ответ отчёта добавлены `measuredConsumption`, `calculatedConsumption`, `resetFilledConsumption`,
  `metersWithBoundaryGap`, `metersWithoutStatus`.

## 1.0.6 — 2026-08-04

### Исходная версия
- Тепловая карта энергопотребления (почасовой и посуточный вид), выбор счётчиков по маскам,
  суммирование, экспорт CSV.
- Отчёт Calculated Data Report по группам счётчиков (E1000…E1850) с подсчётом доли расчётных
  значений по часам без связи.
