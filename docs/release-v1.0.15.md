## 1.0.15 — первая публичная версия

Аддон для WebCTRL: тепловая карта энергопотребления и месячный отчёт о доле расчётных
(восстановленных статистикой) значений по группам счётчиков.

### Что внутри

- **Тепловая карта**: почасовой и посуточный вид, выбор счётчиков по маскам, суммирование,
  экспорт CSV. Пропуски связи заполняются медианой по тому же часу суток.
- **Calculated Data Report**: наработка, измеренный и расчётный объём, процент по каждой группе
  счётчиков (E1000…E1850), число счётчиков с задетыми границами месяца и без тренда статуса.
- **Методика**: месяц = показание на конец минус показание на начало; расчётным считается объём
  граничных блоков без связи; пропуски в середине месяца не учитываются; объём от сбросов счётчика
  восстанавливается, но в числитель не входит.
- **Определение обрыва**: тренд `com_st_min` (полярность настраивается) либо признак «замерший
  счётчик» — блок часов без прироста на границе месяца (порог настраивается, по умолчанию 12 ч).
- Все расчёты в зоне `Europe/Moscow`.

### Установка

1. Скачать `Energyheatmap.addon` из этого релиза.
2. Положить в WebCTRL **без переименования** — имя файла задаёт контекст `/Energyheatmap`,
   а путь к сервлетам зашит в JSP. Переименование ломает отображение (403).
3. Проверить: `http://<server>/Energyheatmap/info.xml` → версия `1.0.15`.

### Требования

WebCTRL с Tomcat 9, JDK 11+ для сборки. SDK-библиотека Automated Logic в репозиторий не входит
(см. `lib/README.md`).

### Известные ограничения

- Цифровой тренд статуса на серверной стороне местами не читается целиком
  (`Record has unexpected value type of 0`) — поэтому он читается по суткам от краёв месяца.
- Признак «замерший счётчик» — эвристика: у счётчиков с объективно нулевым потреблением блок
  без прироста может быть ложным, порог настраивается.
- Отчёт по одному гипермаркету за месяц считается 35–55 с.
